# Ice Fish Girl

Два Spine-примера на PixiJS 8 с оверлеем метрик производительности.
Живая версия: https://rekbrjdf.github.io/ice-fish-girl/

```bash
npm ci
npm run dev      # http://localhost:5173
npm run build    # сборка в dist/
```

Пример выбирается селектом в панели слева:

- **Ice fish girl** — один скелет `assets/anims_v23/fishing.json`, показаны только слои девочки.
- **Background scene** — скелет `assets/background/spine.json`, фоновые режимы циклически
  сменяют друг друга через кроссфейд.

## Панель метрик

Значения усредняются по окну в 500 мс (`interval` в `attachStats`), затем счётчики
сбрасываются. Поэтому любое число в панели — это среднее или максимум за последние
полсекунды, а не за всё время работы.

### frame — плавность анимации

| Параметр | Что это | Как связано с анимацией |
| --- | --- | --- |
| `fps` | Кадров в секунду за окно | Основной показатель плавности. Зелёный при ≥55, жёлтый при ≥40, красный ниже: на красном анимация уже визуально дёргается |
| `ms` (рядом с fps) | Средняя длительность кадра | Обратная величина к fps. Бюджет на 60 fps — 16.7 мс; всё, что сверху, означает пропущенные кадры |
| `fps min / max` | Разброс мгновенного fps внутри окна | Большая разница при нормальном среднем fps означает неравномерность: анимация идёт рывками, хотя средний показатель выглядит хорошо |
| `frame max` | Самый долгий кадр окна | Прямая мера заметного фриза. Пик на смене режима фона — это загрузка текстуры или сброс позы скелета |
| `cpu (js+submit)` | Время JS в кадре: пересчёт костей Spine, обход слотов, формирование команд отрисовки | Растёт от числа костей, от `applyVisibility` (обход всех слотов каждый кадр) и от микширования анимаций. Если `cpu` близко к `ms`, узкое место в процессоре, а не в GPU |
| `gpu` | Время GPU-работы кадра через `EXT_disjoint_timer_query_webgl2` | `n/a`, если расширение недоступно (типично для Safari). Высокий `gpu` при низком `cpu` означает, что тормозит заливка пикселей: крупные текстуры, прозрачность, antialias |
| `long frames >33ms` | Счётчик кадров длиннее 33.4 мс | Накопительное число явных провалов. Каждая единица — это кадр, который зритель воспринимает как подвисание |

### render — цена отрисовки кадра

| Параметр | Что это | Как связано с анимацией |
| --- | --- | --- |
| `draw calls` | Число вызовов `drawElements` / `drawArrays` за кадр | Spine рвёт батч на каждой смене текстуры или режима смешивания между слотами. Чем больше вызовов, тем дороже кадр при том же количестве геометрии |
| `triangles` | Треугольников за кадр | Зависит от mesh-аттачментов в текущей позе. Меняется по ходу анимации, когда слоты скрываются и появляются |
| `texture binds` | Переключений текстуры (`gl.bindTexture`) за кадр | Косвенно показывает, насколько атлас разложен неудачно: при нескольких страницах атласа (`fishing_girl.png` + `fishing_girl_2.png`) переключения растут вместе с draw calls |
| `canvas` | Размер холста в CSS-пикселях и множитель `resolution` | Пересчитывается при ресайзе окна; от него зависит масштаб скелета в `layout()` |
| `pixels` | Итоговое число физических пикселей (`width × height × resolution²`) | Главный множитель нагрузки на GPU. Удвоение `resolution` даёт вчетверо больше работы на заливку, и `gpu` растёт соответственно |

### spine — размер скелета

| Параметр | Что это | Как связано с анимацией |
| --- | --- | --- |
| `bones` | Костей в скелете | Пересчитываются каждый кадр целиком, независимо от того, видны ли они. Прямо влияет на `cpu` |
| `slots` | Слотов в скелете | Обходятся каждый кадр в `applyVisibility`, тоже вне зависимости от видимости |
| `attachments` | Видимых аттачментов | В примере с девочкой считаются только слоты с `color.a > 0`, то есть реально рисуемые. Включение чекбокса `rig` увеличивает это число, и вместе с ним растут `draw calls` и `triangles` |

### memory и context

| Параметр | Что это |
| --- | --- |
| `js heap` | Занято / лимит JS-памяти. Только Chromium, иначе `n/a`. Растущее значение между сменами примера указывает на утечку: не освобождённый `Application` или текстуры |
| `renderer` | Фактический бэкенд: `WebGL2`, `WebGL` или `WebGPU` |
| строка под `renderer` | Имя GPU из `WEBGL_debug_renderer_info` — полезно, чтобы отличить дискретную карту от интегрированной при сравнении замеров |
| `mode` → `background` | Текущий режим фона, появляется только во втором примере |
| `rig` | Чекбокс показа удочки (слоты с путём, начинающимся на `udochka/`). Влияет на `attachments`, `draw calls`, `triangles` |

Кнопка `▴`/`▾` сворачивает панель до fps, draw calls и triangles — так меньше реакции
React на каждое обновление метрик, если нужно мерить в чистоте.

## Параметры в коде

### `src/girl.ts`

| Константа | Значение | Эффект |
| --- | --- | --- |
| `SKELETON`, `ATLAS` | `/assets/anims_v23/…` | Пути к данным Spine. Атлас должен лежать рядом со своими png, иначе загрузка упадёт |
| `GIRL_SLOTS` | набор имён слотов | Белый список того, что остаётся видимым. Остальным слотам выставляется `alpha = 0`, они по-прежнему считаются на CPU, но не рисуются |
| `RIG_PREFIX` | `udochka/` | Префикс пути аттачмента, по которому слот считается частью удочки и управляется чекбоксом `rig` |
| `GIRL_ANIMATION` | `2x_6x` | Проигрываемая анимация. Названия в этом скелете соответствуют диапазонам множителей: `2x_6x`, `7x_10x`, … `280x_950x` и варианты `_gold` |
| `GIRL_SKIN` | `Blue` | Скин, применяется только если найден в данных скелета. Меняет набор аттачментов, то есть и `triangles` |

### `src/background.ts`

| Константа | Значение | Эффект |
| --- | --- | --- |
| `BACKGROUND_SKELETON`, `BACKGROUND_ATLAS` | `/assets/background/…` | Данные фонового скелета. Доступные анимации: `regular_bg`, `free_spins_bg`, `hot_mode_bg_idle`, `hot_mode_bg_start`, `regular_snake_animation`, `free_spins_snake_animation` |
| `BACKGROUND_MODES[].texture` | jpg-фон | Статичная подложка под спайном, растягивается по принципу cover |
| `BACKGROUND_MODES[].animation` | имя анимации | Накладывается поверх своей текстуры. Имя обязано существовать в скелете, иначе Spine бросит `Animation not found` на старте перехода |
| `BACKGROUND_MODES[].title` | подпись | Показывается в панели как текущий режим |
| `BACKGROUND_CYCLE_MS` | `4000` | Сколько режим держится до начала следующего перехода. Должен быть больше `BACKGROUND_CROSSFADE_S`, иначе новый переход запросится до завершения текущего и будет отброшен |
| `BACKGROUND_CROSSFADE_S` | `0.7` | Длительность кроссфейда. Альфы считаются симметричной кривой `easeInOut`, поэтому встречные слои в сумме всегда дают 1 и картинка не проседает в середине перехода |

### Настройки рендера в `GirlStage.tsx` и `BackgroundStage.tsx`

| Параметр | Значение | Эффект |
| --- | --- | --- |
| `resolution` | `min(devicePixelRatio, 2)` | Резкость против нагрузки. Ограничение двойкой не даёт получить вчетверо больше пикселей на экранах с DPR 3+ |
| `antialias` | `true` | Сглаживает края mesh-аттачментов, добавляя работы GPU — видно по метрике `gpu` |
| `preference` | `"webgl"` | Принудительный WebGL. На `"webgpu"` метрика `gpu` станет `n/a`, потому что таймер завязан на WebGL-расширение |
| `backgroundAlpha` | `0` | Прозрачный холст, фон берётся из CSS страницы |
| `autoDensity` + `resizeTo: host` | — | Холст сам тянется за контейнером; на каждый ресайз срабатывает `layout()` и скелет пересчитывает масштаб |
| `spine.state.data.defaultMix` | `0.15` с | Длительность микширования при смене анимации в примере с девочкой. Ноль даст мгновенное переключение с рывком, большие значения — вязкий переход |
| `step` в `animationBounds` | `1 / 15` | Шаг сэмплирования позы при вычислении габаритов анимации. Выполняется один раз при инициализации: мелкий шаг даёт точнее кадрирование, но дольше старт |
| множитель `0.9` в `layout()` | — | Отступ вокруг девочки, чтобы анимация не упиралась в края холста |
